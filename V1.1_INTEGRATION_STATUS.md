# V1.1 / Stage 3 Integration Status

## Base selection
- Primary base: `OKX_SMART_TRADING_V1_1_STAGE2.zip`.
- V1.0 main is retained as comparison/reference only.
- Stage1 integrated archive is a reference only; Stage2 contains the later
  EMA5/EMA10 and 1D/3D/7D daily relative-strength updates.
- Original V1.0 LONG-A/LONG-B/SHORT-A/SHORT-B names and strategy engine remain.

## Existing V1.1 components retained
- Four independent radar evaluators in `strong_radar.py`.
- `relative_strength.py`, `liquidity_filter.py`, `signal_lifecycle.py`.
- Existing OKX public market-data client, Flask dashboard, scheduler,
  LINE notifier, risk manager and database abstraction.

## Stage 3 integration
- Four V1.1 radars are exposed independently from the four V1.0 strategies.
- Pattern scanner uses confirmed 1W/1D/4H/1H candles.
- Harmonic ratio engine includes Gartley, Bat, Alternate Bat, Butterfly,
  Crab, Deep Crab, Cypher and 5-0.
- PRZ alerts are explicitly early alerts and do not contain an entry plan.
- Double top/bottom and head-and-shoulders now distinguish forming from
  neckline-close confirmation.
- Three-drive detector requires three progressive legs and a structure break
  for confirmation.
- Added first-pass wedge/triangle, bull/bear flag, range breakout/breakdown,
  retest and false-break detectors.
- XABCD reversal confirmation now uses the latest closed candle and its
  immediate predecessor; stale post-D candles cannot trigger a fresh signal.
- Pattern invalidation is based on the D point plus an ATR buffer when a
  confirmed harmonic pattern is routed through the existing risk manager.
- Dedicated `pattern_history` persistence records state updates idempotently.
- Scheduler saves pattern lifecycle candidates separately from executable
  simulation signals; incomplete PRZ alerts are not inserted into
  `signal_history` as if they were entry plans.
- Dashboard exposes four V1.1 radar lists and pattern candidates.
- All added paths remain simulation-only; no live order API is called.

## Explicitly incomplete
- Textbook Shark O-X-A-B-C-D detection is not implemented; XABCD-only
  approximations are deliberately not labelled as textbook Shark.
- Full Elliott Wave labelling is not implemented; it remains a future
  auxiliary module.
- Wedge/triangle/flag/retest candidate algorithms require expanded labelled
  historical validation before being treated as production-grade.
- Divergence/volume confluence is not yet enforced consistently for every
  pattern family.
- Pattern-specific walk-forward backtesting with fees, slippage and funding
  is not yet complete.
- Complete pattern lifecycle handling for expiry, cancellation, TP/SL and
  closed-trade outcome attribution remains to be finished.
- Full Flask/PostgreSQL integration tests, live OKX public API tests and
  Render deployment verification remain outstanding.

## Safety
- `auto_trading` remains false and `LIVE_ORDER_ENABLED` remains false.
- No real trading API credentials or order calls are introduced.
- PRZ alerts are not confirmed entries.
- Confirmed pattern plans use simulation-only risk management.
- No win-rate or profitability claims are made.
